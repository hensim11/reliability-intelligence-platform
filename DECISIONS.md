# Decision log

All entries were adopted for Batch A on 2026-09-15. Revisit with evidence in later batches.

| ID | Decision and rationale | Trade-off / revisit trigger |
|---|---|---|
| A01 | Forecast starts in `(t, t+10m]`, rather than classify current anomalies. This matches proactive investigation. | A fault may already be developing; onset needs a precise domain definition. Revisit against external incident records. |
| A02 | Fix a 15-minute observation window and 10-minute horizon. Long enough for short precursors while retaining actionable lead time. | Initial product assumptions, not empirically optimal values. Compare alternatives explicitly in later research without silently changing the task. |
| A03 | Controlled simulation first, external validation later. It supplies known lifecycles and reproducible experiments. | Synthetic mechanisms and prevalence may be easy to learn and fail in reality. No transfer claim. |
| A04 | Python 3.14, src-layout packaging, NumPy/pandas and pytest. Supports reusable numerical code and later service integration. | Local validation and CI target 3.14; other Python versions are not claimed. Broad dependency constraints permit change; the committed exact snapshot supports reproduction. |
| A05 | Parquet is canonical. Typed UTC timestamps, nullable integer labels and compact columnar scans suit later ML. | Requires PyArrow; CSV evidence remains convenient for review. No database yet. |
| A06 | Separate telemetry, incident catalogue and labels, joined only by explicit keys. An operational allowlist blocks metadata leakage. | Separation alone cannot prevent a future developer from choosing leaking features; Batch B must enforce its own feature contract. |
| A07 | Time-aware evaluation with boundary purging and training-only fitting is mandatory. | Fewer independent evaluation examples; random row splits are prohibited. Exact splits deferred to Batch B. |
| A08 | PostgreSQL is the intended durable operational/prediction store. | More setup than local files; transactions and SQL justify it when online ingestion exists. No placeholder adapter now. |
| A09 | FastAPI is the intended serving interface. | Useful typed Python integration, but concurrency and latency need measurement in Batch C. No API scaffold now. |
| A10 | Keep infrastructure proportional. No Docker/cloud/queue/web frontend in Batch A. | Local workflows precede deployment; explicit package boundaries reduce later restructuring without empty modules. |
| A11 | Seeded per-service stratified schedules with non-overlapping lifecycles; explicit schedules override generation. Four events per service cover all four types. | Coverage-oriented timing and severity are artificial; counts greater than four cycle types. No simultaneous faults within one service. |
| A12 | Onset is the injected fault reaching 70% of its peak severity; active pressure rises to peak then recovery decays. | Ground truth describes a controlled failure state, not a universal SLO threshold. Severity changes metric consequences; some faults may not breach a real SLO. |
| A13 | Right-censor incomplete horizons to nullable labels, even if a positive is already known. Keep history completeness as a separate offline eligibility field. | Conservative exclusion sacrifices some usable positives, but avoids asymmetric end-of-run label rules. |
| A14 | Separate seeded random streams for schedule, shared noise and each service. Save resolved configuration, realised incidents, dependency versions and SHA-256 hashes. | Same seed/config/environment reproduces tables. Changing service order, library versions or simulator version can change values; Parquet bytes can differ between environments. |
| A15 | Immutable output directories and atomic dataset publication. Evidence verifies input hashes. | Re-runs need a new output path; hashes detect alteration but are not cryptographic proof of provenance or authenticity. |
| A16 | No active-incident filtering of raw future targets. Every row follows the same next-start definition. | Operational alert suppression and known-current-incident policy need a separately justified inference-time contract in Batch B/C. |
| A17 | History completeness requires exact service-specific membership of every configured telemetry-grid timestamp in `(t−15m,t]`. Elapsed coverage and row count are insufficient. The current timestamp is required, and no observation after t participates. | Gaps remain unfilled and make affected prediction times ineligible. Imputation, irregular-stream policies and arrival-time semantics remain explicit Batch B/C decisions. |
| A18 | A valid generated bundle must contain exactly the Cartesian product of configured half-open timestamps and service IDs, ordered by ascending `(timestamp, service_id)`. Derived history flags do not substitute for raw-grid validation. | This strict generated-bundle contract rejects partial or irregular telemetry rather than representing it. A future ingestion contract may preserve imperfect real streams separately, but cannot silently present them as canonical generated data. |

## Batch B — 2026-09-15

| ID | Decision and rationale | Trade-off / revisit trigger |
| --- | --- | --- |
| B01 | 49 metric-major float64 features: seven allowed telemetry metrics × current/mean/population-std/min/max/change/slope. Exact per-service one-minute windows; gaps are ineligible and off-grid input fails. | Compact interpretable family still contains correlated summaries; only Batch B is restricted to one-minute sampling. |
| B02 | Omit both service encodings and clock/calendar predictors in every candidate; retain them as non-feature keys. Publish per-service diagnostics. | Baseline telemetry can proxy identity; schedule holdout does not replace unseen-service evaluation. |
| B03 | Four chronological stages: train, calibration, selection validation, untouched temporal test; retain t only when t−15m >= start and t+10m < exclusive end. | Conservative purging loses boundary positives; exact timestamp logic is tested, not row offsets. |
| B04 | Three development seeds, two held-out seeds, two held-out renewal-like schedule seeds, each four days. Preserve simulator equations. | 846 events support a small controlled comparison, but only seven independent simulations and the same service profiles. Joint regime changes cannot isolate causes. |
| B05 | Constant prevalence, standardised L2 logistic regression and restricted histogram boosting; fixed hyperparameters, no search or early stopping. | Nonlinear boosting is justified by interacting stress signals; fixed settings avoid an extra tuning stage. |
| B06 | Compare raw probabilities with a two-parameter sigmoid fitted only on calibration rows; require validation Brier AND log-loss improvement to select it. | Simple finite-sample mapping may not repair shape-dependent miscalibration. Reference raw boosting remains selected. |
| B07 | Primary ranking is average precision; select raw family on validation AP, then probability variant. Persist all models and thresholds before test/holdout prediction. | Holdout results can challenge the conclusion but cannot revise the frozen choice; future selection needs fresh holdouts. |
| B08 | Group consecutive alerted eligible minutes into episodes; any in-window alerted minute may detect onset, earliest qualifying minute gives lead. Exposure is eligible service-days; no truth-based suppression. | Long always-on episodes can match many events. Read episode metrics with row precision and alert minutes. |
| B09 | Fixed threshold grid; maximise validation detection under one false episode/service-day, then minimise minutes, then maximise threshold. | Exploratory rule admits always-on prevalence/logistic baselines and does not guarantee final budget. Retain disclosed result; a future preregistered rule needs a hard burden cap and fresh holdouts. |
| B10 | Whole-run bootstrap retains shared service noise and minute correlation. 200 seeded resamples, reported only with at least two runs. | Two or three independent runs per partition give coarse, unstable descriptive intervals. No real-world uncertainty claim. |
| B11 | Trusted-local joblib pipeline/calibrator plus versioned schema/JSON sidecar/hash; strict inference feature check; atomic immutable experiment/evidence directories. | Python binary loading is unsafe for untrusted files; hashes are integrity, not authenticity. Exact sklearn version required; other versions recorded. |
| B12 | Save all candidate keyed predictions and operational scores; commit only compact evidence and source/config/version manifests. | Raw tables and binary models are ignored but reproducible; remote CI and Batch C serving remain unimplemented/unrun. |
